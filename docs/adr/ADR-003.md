## Context

The frontend uses **axios 1.x** ([14.32 KB gzip](https://bundlephobia.com/package/axios@1.18.1)) for all HTTP communication with the backend. Axios wraps the native `fetch` API, but the project already targets modern browsers (Google OAuth, Firebase, PWA) where `fetch` is universally available.

Goals:
- Reduce bundle size: axios sits in the main index chunk; removing it shrinks the critical path.
- Keep the developer API — `apiClient.get<T>()`, interceptors, error shape — to minimise code churn.
- Preserve all axios features used in the codebase: interceptors (auth token, 401 handling, Sentry), upload progress, DELETE with body, per-request timeout, `withCredentials`.
- Unlock a plugin ecosystem for features the codebase currently lacks: error retry, request deduplication, response caching, and mock support — all available as xior plugins.

## Options Considered

### axios 1.x ([bundlephobia](https://bundlephobia.com/package/axios@1.18.1))

**14.32 KB gzip.** Interceptors ✅, upload progress ✅, DELETE body ✅, timeout ✅. Requires no migration effort. The only real option if we value zero churn over bundle size.

### xior 0.8.3 ✓ ([bundlephobia](https://bundlephobia.com/package/xior@0.8.3))

**3.08 KB gzip.** All axios features used in this codebase are supported natively:
- Request/response interceptors (`apiClient.interceptors.request.use()`)
- Upload/download progress via `xior/plugins/progress`
- DELETE with `{ data }` body
- Per-request and global `timeout`
- `withCredentials` mapped to fetch's `credentials: 'include'`

Beyond parity, xior provides capabilities axios does not:
- **Plugin ecosystem** — error retry, request deduplication, throttling, response caching, error cache, and a mock plugin. These are composable and per-request configurable.
- **fetch-native** — works in Service Workers, Cloudflare Workers, Bun, Expo, and React Native environments where XHR (axios's transport) is unavailable. Important for the project's PWA/service-worker architecture.
- **TypeScript-first** — fully typed with strict TypeScript support.

The API surface is axios-compatible. Service files need no changes — only `apiClient.ts` is rewritten. Based on `fetch`, actively maintained ([GitHub](https://github.com/suhaotian/xior), 307 commits, frequent releases), last published June 2026.

### ky 2.x ([bundlephobia](https://bundlephobia.com/package/ky))

**7.21 KB gzip.** Interceptors via hooks (`beforeRequest`, `afterResponse`). Fluent/options-based API — requires rewriting all 22 service files. Rejected for migration cost.

### ofetch 1.x ([bundlephobia](https://bundlephobia.com/package/ofetch))

**3.88 KB gzip.** Closest to `fetch` API. Interceptors via `onRequest`/`onResponse`. Still requires rewriting service files. Rejected for migration cost.

## Decision

Replace axios 1.x with **xior 0.8.3**.

## Bundle Size Impact

Build with `axios@1.18.1` vs `xior@0.8.3`. Only `package.json` and `apiClient.ts` differ.

| Chunk | Before (axios) | After (xior) | Delta |
|-------|----------------|--------------|-------|
| `vendor-*.js` | 721.52 kB (227.49 kB gz) | 721.52 kB (227.49 kB gz) | 0 kB |
| `index-*.js` | 355.39 kB (92.35 kB gz) | 322.69 kB (79.84 kB gz) | −32.70 kB (−12.51 kB gz) |
| **Total precache** | 4794.06 KiB | 4761.09 KiB | −32.97 KiB |

Axios was bundled into the main index chunk; removing it shrinks the entry point by ~12.5 KB gzipped (~13.5% reduction). The vendor chunk (React, MUI, Firebase) is unchanged.

## Implementation

`src/services/apiClient.ts` uses `xior.create()` and replicates the original axios instance's behaviour:

- **`withCredentials: COOKIE_AUTH`** — sends the httpOnly session cookie in cookie-auth mode. Unchanged from axios config.
- **Request interceptor** — injects `Authorization: Bearer <token>` from `useAuthStore.getState().token`. No-op in cookie-auth mode where the store's token is null.
- **Cookie-auth token refresh** — on 401 in cookie mode, attempts `/auth/refresh` once with a de-duplication promise (prevents concurrent refreshes from racing). Uses a bare xior instance (`refreshClient`) to avoid re-entering this interceptor. Auth endpoints (`/auth/me`, `/auth/refresh`, `/auth/logout`, `/auth/google/exchange`, `/auth/admin/login`) are excluded from refresh. Falls back to `clearSession()` if refresh fails.
- **Legacy header-auth** — on 401 in legacy mode (no cookie), calls `logout()` directly.
- **Network/timeout errors** — normalises `error.message` to a developer-readable diagnostic string (`[AbortError] GET /api/aspirants — The user aborted a request`) via `describeNetworkError()`.
- **Sentry reporting** — reports only network/timeout failures and 5xx server errors. Skips 4xx and 401s (expected client errors). Request/response bodies are never sent.
- **Upload progress** — registered via `apiClient.plugins.use(xiorProgressPlugin())`. Supports `onUploadProgress` in request config transparently.
- **DELETE with body** — `apiClient.delete(url, { data })` works natively.

`src/store/useAuthStore.ts` — removed 4 blocks that called `apiClient.defaults.headers.common.Authorization` to set/clear the Bearer token. This responsibility moved to the xior request interceptor, which reads `useAuthStore.getState().token` directly on every request. The `import apiClient` statement was removed as dead code.

## Consequences

**Positive:**
- Main entry chunk shrinks by ~12.5 KB gzipped (13.5%).
- All axios features used by the codebase are supported natively — no custom fetch wrapper, no Zustand store for interceptors.
- `apiClient.ts` is the only file rewritten; no service-file changes required.
- `onUploadProgress` in `SopUploadPage.tsx` works transparently via the xior progress plugin — no XHR fallback needed.
- Plugin system enables incremental adoption of error retry, request deduplication, and caching — all zero-cost until opted in.

**Negative:**
- Team must be aware that `apiClient` is now a xior instance. Methods absent from axios are also absent here (`axios.all`, `CancelToken`, `isAxiosError`) — none were used.
- xior has a younger ecosystem than axios. The [GitHub repository](https://github.com/suhaotian/xior) is actively maintained (commits as of June 2026) with a responsive maintainer, but has fewer community resources.
